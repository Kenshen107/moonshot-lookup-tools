# Moonshot Lookup Tools

Fan-made tools, used at Moonshot Games' two stores (Noblesville and Plainfield). The owner made them; Moonshot Games didn't, so **nothing should read as if the store made or runs them** (owner, 2026-10-05). Store links (stock searches, Shop, event calendars), hours and the store's values stay, written as information about the store, and each page says it's fan-made. Each tool is a single self-contained `.html` file with no build step. They call Scryfall's public API directly from the browser. Changes merged to `main` go live on GitHub Pages.

## Working in this repo

- Keep each tool a single self-contained HTML file. Don't add frameworks, build steps, or a backend. **The one exception is Spellslinger Duels** (owner's OK, 2026-10-08): it is now the page `Spellslinger_Duels.html` plus plain script files and a stylesheet in `spellslinger/` (see below). Still no frameworks, no build step, no modules. The one exception is the daily market data job (see below), which the owner approved on 2026-09-25: it only produces data files, and the HTML stays a single file.
- In `MTG_Lookup_Tool.html`, tabs are driven by the `APP_VIEWS` table (each entry has an icon, a menu label and a one-line description). `NAV_GROUPS` puts every tool except Card Lookup into one of three groups (At the counter, Rules & events, Learn & train); the desktop menu bar, the phone bottom bar and the quick-jump search (`/` or Ctrl+K) are all built from these two tables. `QUICK_JUMP_EXTRAS` adds sub-tabs and sections to quick jump. The Buyer's Guide and Grading tabs use sub-tab tables (`BUYERS_GUIDE_SUBTABS`, `GUIDE_SUBTABS`). Reuse the existing helpers (card tiles, the card popup, the Moonshot store links `moonshotLinkHTML` / `moonshotBlockHTML`, `fetchScryfallSearchPage`) instead of writing new copies.
- **Layout and design rules (cleanup of 2026-10-05):**
  - The page top is a slim utility row (Pokémon tool, Beginner guides, Shop, 🏪 About Moonshot Games, ✨ Effects), then the store bar (the store's name as text, not its logo). On phones the store bar is one row; the locations fold behind "📍 Hours & locations" (`toggleStoreBar`).
  - The desktop menu bar is sticky and holds "📦 Moonshot Search"; on phones it's the "Stock" item in the bottom bar. Both open `#quickStockPanel` (Esc closes it). There are no floating buttons; don't add new ones, since they cover content.
  - Use the design tokens in `:root` for every color (`var(--...)`), never new hex values outside the theme blocks, so seasonal themes reach every part of the page. `--text-soft` is for notes that must stay readable (`.bk-note`, hints); `--color-warning` is amber.
  - Text sizes use a short scale (0.72 / 0.8 / 0.85 / 0.9 / 0.95 / 1 / 1.1 / 1.2em and up), and corners use `--radius-sm/md/lg`. Notes under panels are at least 0.85em.
  - The prerelease print card (`.pr-dc`) and print CSS keep their own fixed colors and sizes; leave them out of these rules.
  - The seasonal decorations layer (`#seasonalFx`) is masked to the side margins so it never crosses content.
  - "🏪 About Moonshot Games" opens a panel with both stores' addresses, hours, phone numbers and event calendars, and the store's values in third person ("what the store says it stands for"). It never opens by itself (it used to on every visit). Each tool ends with a fan-made note (`.site-note` in the MTG tool, `.pk-legal-note` in the Pokémon tool, `footNote` in Beginner Guides).
  - Visual effects (✨ Effects: Full / Subtle / Off) are described under "Visual effects" below; they also read only the tokens.
  - Card Lookup: the card image is sticky on desktop; jump chips under the name (`jumpToCardSection`) open and scroll to each section. Legality chips use a colored edge plus a one-line label (`renderLegalityGridHTML`, shared with the popup and Format Rules). A card with no rulings shows a plain "Rulings: none" line.
- Moonshot stock isn't checked live. Shopify doesn't let other sites read the store, and the free CORS relays that worked around that were unreliable, so the tool links to moonshotgamestore.com's own search instead. Don't bring back third-party relays. A live check would need a Shopify Storefront API token from the store admin.
- Scryfall search queries (otags especially) can't be guessed reliably. Mark anything not checked against live results as unverified or approximate, as the land-cycle data already does.
- Claude's cloud environment can reach `api.scryfall.com`, so check new or changed Scryfall queries against live results before shipping them. The Land Finder's fixed cycles use exact card-name lists (`LAND_CYCLE_CARDS`), checked live on 2026-09-24.

## Pokémon tool (`Pokemon_Lookup_Tool.html`, rebuilt 2026-10-05)

Rebuilt on the MTG tool's layout (owner's request): the same utility row, store bar, sticky menu bar / phone bottom bar, Moonshot Search panel, design tokens and seasonal themes (the CSS and the `<head>` theme script are copied from the MTG tool, so copy changes across when those change). Tools are in `PK_VIEWS`; on phones, Learn opens a sheet with Learn to Play, Rarity Guide and Staff Quiz (`PK_LEARN_GROUP`). `#sets`, `#learn`, `#rarity`, `#deck`, `#quiz`, `#card=<id>` and `#set=<id>` open a view.

- **Data: TCGdex only** (`api.tcgdex.net`, free, no key, browsers can call it). pokemontcg.io was dropped: its team moved to a paid successor and the free API was timing out and returning 502s (checked 2026-10-05). The GraphQL endpoint (`pkGql`) returns every set in one request (`loadPkSets`) and every card in a set in one request (`loadPkSetCards`, an `id` filter on `"<setId>-"`, then keep the exact set). Single cards, with prices, come from REST (`loadPkCard`). Pokémon TCG Pocket (series `tcgp`) is left out.
- **Set codes:** Scarlet & Violet and Mega Evolution cards print a set code (OBF, POR) instead of a symbol. `PK_SET_CODES` is a snapshot from TCGdex's set pages (checked 2026-10-05); sets newer than it get their code live (`loadPkMissingCodes`, cached a week). Older sets use TCGdex's `tcgOnline` code. Symbols: TCGdex's picture, else pokemontcg.io's image server for pre-SV sets (approximate id mapping), else a code box (`pkSymbolHTML`).
- **Card Lookup:** one search box (`parsePkQuery`) takes a name, a set code (opens the set), a code + number (`OBF 125`) or a printed number (`125/197`, which lists every set of that size). The card view shows "📍 Where it lives" (era › set › A–Z letter and neighbors), because the stores file singles by era, then set, then alphabetically (owner, 2026-10-05). Prices are TCGplayer per finish (and Cardmarket trend) from TCGdex, with the update date. The Moonshot link searches the store by name (stock isn't read live; the old CORS relays were removed).
- **Set view:** sets before/after, a Cards A-Z (binder order) stepper, and the whole set sortable A-Z / number / rarity with a rarity filter. TBC Games' printable checklists (`POKEMON_SET_REFERENCE`) are kept.
- **Learn to Play:** rephrased from the 2026 Pokémon TCG web rulebook the owner pasted on 2026-09-30 (basics, a 4-step turn walkthrough, Special Conditions, card types and Prize counts, deck building). Standard-legal regulation marks come live from TCGdex (`loadPkLegalMarks`; H, I, J on 2026-10-05). Expanded = Black & White onward (TCGdex data).
- **Rarity Guide:** real card corners (`pkCornerHTML`, a CSS crop of TCGdex's card image). The symbol descriptions in `PK_RARITIES` were checked by eye against the example cards on 2026-10-05.
- **Deck Checker:** reads Pokémon TCG Live lists (`parsePkDeckList`): 60 cards, 4 per name (Basic Energy exempt), at least 1 Basic Pokémon, 1 ACE SPEC, 1 Radiant, Standard legality per card (a printing that isn't legal shows "via reprint" when a same-name reprint is), and cards with the oldest legal mark flagged "rotates next".
- **Staff Quiz:** which set / what rarity / Standard legal, from the corner of a random recent card.
- **Products** (added 2026-10-13, owner's request to mirror the MTG Products tab as far as possible; `PK_PRODUCTS`, `renderPkProducts`, `#products`): a guide to each kind of sealed product (Booster Pack, Bundle, Booster Box, Elite Trainer Box, Build & Battle Box, Tin, Premium / Special Collection, Blister, Battle / Theme Deck, accessories): what's typically inside, what it's for, a tip, grouped with filter chips. **Limitation:** there's no free source for Pokémon sealed contents (MTGJSON is Magic-only, TCGdex has cards only), so it's hand-written from how current products are usually built (`PK_PRODUCTS_AS_OF`, 2026-10-13), counts are typical and approximate, and the page says so; no photos, pull rates or box-value numbers. An optional set picker (from `loadPkSets`) adds the set name to each product's Moonshot store search link. Recheck the counts when a new product line launches.
- **Legal:** text says it's unofficial and not affiliated with The Pokémon Company, Nintendo, Creatures or GAME FREAK, and credits TCGdex.

## Products tool (`MTG_Lookup_Tool.html`)

Sealed product data (what's in each box, bundle, deck and kit) comes live from MTGJSON (`mtgjson.com/api/v5/SetList.json.gz`, which browsers can read directly). Commander decklists come from the per-set files (`<CODE>.json.gz`), loaded only when a decklist is opened. Photos come from TCGplayer's image CDN via each product's `tcgplayerProductId`. Buy-a-Box and Bundle promos come from Scryfall. Nothing is hand-maintained, so new sets show up on their own.

**Precon prices and reprint value:** opening a decklist prices every card at its exact printing in the deck (the foil price where the deck's copy is foil). It uses Scryfall's `/cards/collection`, 75 printings per request (`loadDeckPrintings`), which returns Scryfall's daily TCGplayer market price and its `reprint` flag. The list and picture views show each card's price. Cards worth `REPRINT_VALUE_MIN` ($5) or more are flagged: reprints get a gold 💰 Reprint badge, and cards first printed in this product get a blue 💎 New badge (as a frame in picture view). A box at the top lists both groups, most valuable first, with the deck's total value split into reprints and new cards. The commander shows its price too. **New decks (added 2026-09-28):** a printing with no price yet (common before a deck releases) uses the card's cheapest other printing instead (`deckFallbackCache`, filled by `loadDeckFallbackPrices` via `cheapestPrintings`). Those prices show as `~$x` in italics, with a tooltip naming the set they came from; they count toward the flags and deck total, and the value box says how many are estimates. Brand-new cards with no printing priced anywhere still show "—" and aren't counted. A "By type / 💲 By price" toggle switches between the grouped list and one list sorted most valuable first (`productDeckSort`), in both list and picture view.

## Set view in Card Lookup (`MTG_Lookup_Tool.html`, added 2026-10-04)

Typing a set code (`FRA`, or `set:fra` / `e:fra`) into the Card Lookup search opens the set instead of a card (`openSetView`). The autocomplete shows the set as its first suggestion. The page shows, in this order (owner's choice):
- **Sets before and after:** by release date among sets of the same kind: main sets (core + expansion) for a main set, otherwise the same Scryfall set type (`setViewNeighbors`). Digital-only sets are skipped unless the set is one. Non-main sets also show the main sets around them, plus related sets (tokens, promos, Commander).
- **Cards A–Z:** a stepper through the set's cards in alphabetical order, one entry per name (`setAzList`), with a "Jump to" dropdown and "Full lookup", which opens that exact printing (`showCardInLookup`), not the newest one.
- **Whole set:** a drop-down list of every printing Scryfall has for the set (`loadSetCards`, `e:<code>` with `unique=prints`, up to `SET_VIEW_MAX_PAGES` pages). It can be sorted by number, A–Z, rarity or price and shown as a list or pictures; the card popup's arrows step through it.
- ICE and WHO are also card names (Fire // Ice, Who // What // ...), so the set view links to the card too. A card view's "Sets released around this one" box also shows the card's A–Z neighbors in its set (`loadCardAzNeighbors`) and a link to open the set.

## EDHREC data (`MTG_Lookup_Tool.html`)

Commander play data comes live from EDHREC's JSON feed (`json.edhrec.com/pages/...`, which browsers can read directly). EDHREC has no official API, so every EDHREC panel is optional. If a page is missing or the feed changes, the panel shows nothing and the rest of the app keeps working. Always credit EDHREC with a link, as the panels already do. EDHREC's trend data (such as its weekly top commanders) may be used. Don't use EDHREC's prices. Prices come from Scryfall at the cheapest paper printing (`cheapestPrintings`, which uses `prefer:usd-low`).

- **Card Lookup:** "Commander play" shows how often the card is played and the commanders that play it most. For commanders, "Build around this commander" shows the bracket split, themes, card lists, similar commanders, and EDHREC's budget deck priced at the cheapest copies. A bracket slider under the split (All, 1-5; added 2026-10-04) switches the card lists to EDHREC's page for that bracket (`commanders/<slug>/exhibition|core|upgraded|optimized|cedh`, `EDHREC_BRACKET_PAGES`), built only from decks at that bracket, with that bracket's deck count and Game Changer allowance (`EDHREC_BRACKET_GC_NOTE`). Themes, similar commanders and the budget deck stay on all decks.
- **Card popup:** "Build around this commander" opens Card Lookup with that guide expanded.
- **Products:** "Upgrade this deck" on precon decklists shows the most-played and best-synergy cards for the deck's commander that aren't in the precon.
- **Brackets tab:** the card checker, and the deck checker when the list has a Commander heading or tag, show which bracket EDHREC players build that commander at.
- **Land Finder (Buyer's Guide):** a three-step guide. (1) Start from a commander or pick colors, (2) choose how many nonbasic lands to buy, (3) pick a Good / Better / Best package (`LAND_TIERS`), or type a custom budget. For Commander, lands are ranked by EDHREC's land page for the color identity (`EDHREC_LAND_PAGES`, all 32 checked 2026-09-25). With a commander, its own decks' land lists count first, and step 2 suggests its average nonbasic land count. Better and Best skip lands that always enter tapped unless nothing else fits. Popular EDHREC lands that no cycle search finds are added as "Other popular land". Other formats keep Scryfall's popularity order and show no EDHREC numbers.

## Market data and Market Watch (`MTG_Lookup_Tool.html`)

Scryfall only has today's prices, so price history comes from a GitHub Action (`.github/workflows/market-data.yml`) that runs twice a day, at 13:23 and 20:47 UTC. It runs twice because GitHub skips or delays scheduled runs on busy hours, and MTGJSON's daily prices land at varying times; a run on unchanged prices is harmless. It can also be started by hand (workflow_dispatch). It runs `tools/build_market_data.py`, which downloads MTGJSON's 90-day price history (`AllPrices.json.gz`) and its card, ID and legality CSVs, then publishes small JSON files to the `market-data` branch. The branch is replaced each run, one commit with no history, so the repo doesn't grow. The site reads the files from `raw.githubusercontent.com/Kenshen107/moonshot-lookup-tools/market-data/` (`MARKET_DATA_BASE`). If they're missing, every panel that uses them says so, and the rest keeps working.

- **Price archive (added 2026-10-05, owner's request):** the same job keeps our own copy of each day's prices on the `price-archive` branch, so the data doesn't rest on MTGJSON alone. It keeps the last 60 days (`ARCHIVE_DAYS`, owner's choice: "I don't want it getting too big"), about 0.8MB a day gzipped, so about 50MB in all, replaced each run like `market-data`. `cards.csv.gz` lists every printing (uuid, Scryfall id, name, set, number; rows are only added, so a row number means the same printing in every day file) and `days/<date>.csv.gz` holds that day's TCGplayer, Card Kingdom and Mana Pool retail and Card Kingdom buylist per finish (`ARCHIVE_COLUMNS`). The branch has a README with the format and a short Python reader. Each run reads the archive back in (`load_archive` / `merge_archive`) to fill days MTGJSON's file lacks, adds the newest day and any missing day in the window, and drops older days (`write_archive`). If `AllPrices.json.gz` can't be downloaded, the job uses `AllPricesToday.json.gz` plus the archive instead, and `meta.json`'s `source` says so. The first run seeds it with 60 days from MTGJSON's history. The site doesn't read the archive directly; the chart keeps MTGJSON's 90 days (owner's choice).
- `meta.json` holds the price date, the weekly dates and the daily dates.
- `history/<first 2 chars of Scryfall id>.json` holds TCGplayer market prices per printing and finish, for printings that reached $1: 14 weekly points (`n`, `f`, `e`, about 90 days) and 91 daily points for the last 90 days (`dn`, `df`, `de`; 31 points before 2026-10-05). Other stores for the same printing: `ck<f>` / `mp<f>` hold Card Kingdom / Mana Pool retail as [now, 7 days ago, 30 days ago], and `kb<f>` holds Card Kingdom's buylist as weekly points; `ckd<f>`, `mpd<f>` and `kbd<f>` (added 2026-10-05) hold the same three as 91 daily points for the price chart. The shards are about 475KB each (about 60KB as GitHub sends them, gzipped). A store price more than 2 days old counts as not listed. Read it with `priceHistoryFor(id)`, `finishHistory(history, key)`, `priceTrend(points, steps)` and `priceTrendDays(fh, days)`. The last one uses the daily points when they exist and falls back to weekly.
- `spikes.json` lists printings of $2+ that rose at least $1 and 15% over 1, 3 or 7 days, with Card Kingdom and Mana Pool retail for the same printing (`ck`, `mp`: [now, 1, 3, 7 days ago]).
- `buylist-spikes.json` lists printings Card Kingdom's buylist pays $1+ for, up at least $0.50 and 15%, and higher than a week ago (their buylist often dips and comes back). Capped at 3,000.
- `bans.json` holds the current banned/restricted cards per format, plus a log of changes found by comparing against the previous run. The log starts empty; tracking began 2026-09-25.

Where the data is used:

- **Market Watch tab** (`MARKET_SUBTABS`, under At the counter):
  - Price Spikes. A "Show" dropdown switches between retail price jumps (TCGplayer) and Card Kingdom buylist increases. Filters cover window, jump range, current price range, finish and promos, plus "Hide cards from before 2003" (on by default, using Scryfall's set release dates) and, for retail, "Only if another store is up too" (on by default). That last filter keeps a jump only when Card Kingdom or Mana Pool raised the same printing 10%+ over the same window and that store's price is within 2× of TCGplayer's; each confirming store shows a ✓ badge. It uses ranges rather than "at least" because old, thinly traded cards swing by big dollar amounts and would fill an "at least" list.
  - Ban Watch (ban log, with EDHREC decks and commanders affected and price trend).
  - Trending Commanders (EDHREC `commanders/week`, with each commander's most-used cards priced).
  - New Set Tracker (EDHREC `sets/<code>`, the set's most-played new cards and commanders).
  - Pulled by New Sets (`MKT_PULLED_*`): the older cards a new or upcoming set's commanders pull into decks. It covers upcoming sets (EDHREC tracks previewed cards before release) and sets released in the last 90 days. For the set's 15 most-built new commanders it reads each commander's EDHREC page and keeps cards those decks play at least 15 points more than other decks (EDHREC's synergy). It leaves out the set's own cards, basic lands and EDHREC's 100 most-played staples (`top/year`). "New decks" is the card's share of each commander's decks times that commander's deck count, added up. The default sort, "Most tied to the new set", multiplies that by the card's best synergy so niche pieces rank above generic ones like shock lands. Rows show the driving commanders, the cheapest copy, and a 30-day trend from the market data. It all runs in the browser; no data job changes.
- **Card Lookup:** "Price history" (rebuilt 2026-10-05, `renderPriceHistoryPanel` / `drawPriceChart`) charts one finish at a time (Regular / Foil / Etched buttons) over 7, 30 or 90 days: TCGplayer market plus Card Kingdom sells, Mana Pool sells and Card Kingdom pays as lines that can be switched off (`PRICE_SERIES`, colors `--chart-1..4`, validated with the dataviz palette checker). One shared price scale with at least a 20% band, so a flat card doesn't look volatile; price and date axes; a crosshair tooltip (mouse, touch, arrow keys); a stats row (market now, change, high and low with dates, biggest day move, Card Kingdom pays as % of market); a one-line summary (`priceSummaryText`); numbered markers for reprints in the range (other paper printings' release dates) and ban-log changes; a table view. A store line more than 2x off TCGplayer's price is hidden as "looks off" until switched on. Files from before the 90-day daily data fall back to weekly points. The "Other stores" table below shows each finish with its 30-day change. The All Printings table has a "30 days" column, filled in as each printing's history loads.
- **Buylist:** typing a card name shows its 30- and 90-day trend at the cheapest printing. A move of 15% or more gets an "up" or "down" note. It also shows what Card Kingdom pays for that printing, with its 30-day trend, as a benchmark. A printing in the last 45 days, or an upcoming one (Scryfall includes previewed cards), shows a reprint warning. Values are still typed by hand. The cash percentage starts at 50% and the store-credit bump at 0%. **Per-card rates** (2026-10-13, owner's request, for premium cards): each row has optional "Own Cash %" and "Own Credit +%" boxes after Store Credit (`rowRates`, `computeBuylistOffer(value, row)`; saved in `buylistRows` as `cashPct` / `bumpPct`). Blank means the row follows the rates at the top (the boxes show them greyed out); a row with its own rate is highlighted, and the total adds each row's own amounts. Keep the wording neutral: the tool isn't an official Moonshot tool, so it shouldn't read like store policy.
- **Products:** "Pull rates: what's in each pack" (added 2026-10-04, `computePullRates`) uses the same MTGJSON booster data, no prices. For each pack type (play, draft, set, collector, box topper, prerelease...) it shows cards per pack, packs per box, the pack layout (each slot with its rarity mix and share of special treatments; variant sheets that stand in for each other merge into one row) and a table of everything you can pull, grouped by rarity, treatment (borderless, showcase, extended art, serialized...) and foil type (`PULL_FOIL_TYPES`), plus bonus sheets such as Special Guests by set. Each row has the average per pack, the chance of at least one in a pack, the count or odds per box, and the odds for one specific card. It also shows the main set's size and rarity counts. A product's popup has a "🎲 Pull rates" button on each pack. Checked on FRA, DSK, DMU, M19, MH3 and Alpha.
- **Products:** "Box value: open it or sell it sealed?" computes each booster type's expected card value from MTGJSON's booster sheets and today's Scryfall prices. It shows the total, a "sellable" figure (cards $1+), chase cards, and a comparison against a sealed price staff type in. There's no free source for sealed prices or their history, so there's no sealed trend.
- **Buyer's Guide → Price a Deck:** a pasted list is priced at the cheapest copies, with the total, a 30-day trend per card and a count of rising cards.

## Prerelease tab (`MTG_Lookup_Tool.html`)

The 🎟️ Prerelease tab (under Rules & events, `PRERELEASE_SUBTABS`) works on one set at a time. The set picker lists every set MTGJSON has a prerelease kit for (`subtype: 'prerelease_kit'` in SetList, loaded with `loadProductsData`; Return to Ravnica, 2012, onward), so Masters sets and Mystery Booster Commander, which have no prerelease, stay out. Scryfall expansions and core sets from 120 days back to 120 days ahead are listed too, in case MTGJSON hasn't added a new set's kit yet or can't be reached. It's grouped: Coming up, Out now (last 120 days), and Older sets (for running a prerelease with leftover kits). New sets appear on their own, and sets move to Older after 120 days. It defaults to the next upcoming set; a link can choose the set with `?set=<code>`.

- **Mechanics & Rulings:** for quick judge calls. It shows each mechanic with a plain-English explanation, key rulings and every card that uses it, plus a lookup for any card in the set. Card text comes live from Scryfall. Scryfall only adds official rulings at release, so they appear automatically from release day on. Before that, the hand-written notes in `PRERELEASE_SET_NOTES` cover them. Every set's own mechanics are also found automatically (`prereleaseMechanics`):
  - **What counts:** any non-evergreen keyword on 3+ of the set's cards (`EVERGREEN_KEYWORDS`, `PR_KEYWORD_SKIP`), plus card types that work like mechanics (`PR_MECHANIC_TYPES`: Adventure, Saga, Class, Case, Room, Battle, Spacecraft).
  - **Cycling family:** it's sorted per card (`prCardMechanicKeywords`), so a Forestcycling card counts as Landcycling, not Cycling.
  - **New vs Returning:** set by asking Scryfall how many paper cards had the mechanic before the set's release date. 3 or fewer (`PR_NEW_MECHANIC_MAX_PRIOR`) counts as New, because previews and promos sometimes print one early. New mechanics come first, then the rest by card count.
  - **Explanations:** `PR_MECHANIC_GLOSSARY` (plain English for common and recent mechanics, written with N where the number varies), else the most common reminder text on the set's cards. Ability words without reminder text (Celebration, Eerie) use the condition part of the card text.
  - **Checked on 2026-09-25** against FIN, KTK, MOM, WOE, DSK, BLB, OTJ, LCI, NEO, ONE, DMU, SNC, TDM and FRA. Add glossary entries for new sets' mechanics when the reminder text is card-specific.
- **Hot Cards:** the set's most-played new cards (EDHREC `sets/<code>`), plus the older cards its commanders pull in (the same data as Market Watch → Pulled by New Sets), priced at the cheapest copies.

- **Saved data (Phase 1b, 2026-10-08):** everything the game saves goes through `store.get / set / remove` (`00-storage.js`). The values live in **IndexedDB** (database `spellslinger`, one store `kv`, key = the old name without `duels:`, value = JSON text). They are all read once at start-up into memory (`STORAGE.mem`), so `store.get` stays synchronous and returns a fresh copy; `store.set` updates memory and queues a background write (`STORAGE.flush()` waits for it; tests use it). **First run:** every `duels:*` key in localStorage is copied into IndexedDB (marker `__migrated`) and the localStorage originals are left as a backup; they are not read again. If IndexedDB can't be used the game falls back to localStorage with the old "storage is full" handling (`saveProfile`, `trimCardCache`). Keys starting with `test` (`testListA`) are always read from localStorage so tests can set them. Two tabs no longer see each other's changes until reload. **Later cleanup:** delete the old `duels:*` localStorage keys once nobody needs the backup. Don't call `localStorage` directly in the game.
- **Redraws (Phase 1c, 2026-10-08):** `setHTML(el, html)` (`01-core.js`) sets `innerHTML` only if the HTML changed since the last `setHTML` on that element. `renderGame` uses it for each zone (both bars, both sides, the middle bar, the hand) and runs `fitTable` only when a zone changed or the window, hand size or game mode changed; the shop floor (`renderShopFloor`, `renderGrading`) uses it for each panel. So an unchanged redraw keeps the same page elements: hover, scroll, a half-typed price and an open `<details>` survive, and nothing is re-laid-out. **Rule:** use `setHTML` only on containers nothing else writes to, and don't rely on a redraw to reset something you changed in the page by hand (a class you added): if the HTML is the same, the page is left alone. `node tests/perf.js` times it (table about 17 to 8 ms, shop floor 12.6 to 0.2 ms with a full board and case).

- **The stack** (added 2026-10-05, owner's request; follows the Comprehensive Rules): casting puts a spell on the stack (`castSpell`, CR 601.2); "when this enters" abilities trigger and go on the stack with their targets chosen then (`putTriggers`, 603.3, 603.3d). ## Seasonal themes (`MTG_Lookup_Tool.html`)

The site's colors all come from the design tokens in the `:root` CSS block. A seasonal theme is an `html[data-theme="..."]` block that overrides some of them. The schedule script in `<head>` (`SEASONAL_THEMES` / `SEASONAL_SCHEDULES`) decides which theme is on, by the device's local date, repeating every year. Outside any season there's no `data-theme`, so the site uses the original look. Staff can switch a season off on their own device with the "Switch to classic look" button. Add `?theme=<key>` to the URL to preview any theme.

### Holidays and observances

Holiday themes (`HOLIDAYS` in the `<head>` script) take priority over the fall and winter rotation on their day. The only exceptions are a season's own special days (Christmas Eve/Day, New Year's Eve/Day), which win. Each holiday shows a one-line note under the page title saying what the day is, even in the classic look. Days of remembrance (Memorial Day, Veterans Day) use muted colors and no decorations. If two holidays land on the same day, the one listed first in `HOLIDAYS` wins.
